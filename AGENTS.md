# Research session contract

Read `RESEARCH_STATE.json` and its `required_session_reads` before changing research code, interpreting results or making scientific claims. Update that state and add an append-only development record before ending a research session.

Preserve all existing negative, mixed, inconclusive and invalid evidence, frozen protocols, source identities, failed runs and decisions. A code correction is implementation evidence; it is not a new scientific result and does not reopen a closed predecessor. Respect the specific protected boundary recorded in state.

Use generated fixtures for correctness tests. Do not inspect protected outcomes while developing or retuning a successor. Any behavior-changing scientific run needs its own explicit hypothesis, separately versioned specification, falsifier, source and input identities, finite development budget and pre-outcome confirmatory freeze. Keep historical artifacts and their source bindings intact.

Report exactly which tests ran, their environment and any remaining blockers. Never label a project complete solely because code tests pass. Reconcile existing pull requests before starting overlapping work.
